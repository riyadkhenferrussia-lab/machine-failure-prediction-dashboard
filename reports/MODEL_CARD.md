## Summary

- **Model:** Random forest (raw + engineered features), a scikit-learn `Pipeline` (feature engineering, preprocessing, classifier).
- **Task:** binary classification of the `Machine failure` label of the AI4I 2020 Predictive Maintenance dataset (10,000 records, 339 failures).
- **Output:** a failure score in [0, 1]; a record is flagged when score ≥ **0.349** (the operating threshold). The score is the forest's averaged vote, not a calibrated probability.
- **Trained:** 2026-10-21T18:22:46+00:00 with Python 3.13.16, scikit-learn 1.9.1, pandas 3.0.5, numpy 2.5.3; seed 42.
- **Data file SHA-256:** `59db4f1d9c34c58136d89e5a006ec190dcea19e9dbea74f6b3b0c6f22a44d183`.

## Intended use

Portfolio demonstration of a predictive-maintenance workflow: ranking machine records by failure score so that inspections can be prioritised, with transparent engineering indicators next to the score. A flagged record is a **prediction to be checked by a person, never a confirmed fault**, and the model does not estimate remaining useful life or the cause of a failure.

## Out of scope

- Real-time monitoring, control or any safety-related decision (the project has no live data connection).
- Use on real equipment without re-training and validation on that equipment's own data, units and product mix.
- Treating the score as a calibrated probability (see the reliability figure).

## Data

AI4I 2020 Predictive Maintenance Dataset (S. Matzka, UCI Machine Learning Repository, DOI 10.24432/C5HS5C, CC BY 4.0). The dataset is **synthetic**: the authors generated it to resemble real milling-machine maintenance data, and its failure labels follow documented rules plus random components. Stratified split: 8,000 training records (271 failures) and 2,000 hold-out records (68 failures). The published labels contain 9 records with `Machine failure = 1` but no failure-mode flag, and 18 records with a mode flag (all random-failure flags) but `Machine failure = 0`. They are kept exactly as published and reported as validation warnings.

## Inputs and leakage controls

- Model inputs: `type`, `air_temp_k`, `process_temp_k`, `rotational_speed_rpm`, `torque_nm`, `tool_wear_min`.
- Features derived inside the pipeline from those inputs: `temp_diff_k`, `power_w`, `strain_min_nm` (temperature difference, mechanical power, wear × torque).
- Never given to the model: `machine_failure`, `twf`, `hdf`, `pwf`, `osf`, `rnf`, `udi`, `product_id`. Identifiers and failure-mode flags define or identify the label, so they are excluded by an explicit guard that is covered by automated tests. Mode flags are used only for the after-the-fact per-mode analysis below.
- Scaling, one-hot encoding, the classifier, hyper-parameters and the decision threshold are all fitted on training data only. The hold-out set is evaluated once, after every choice has been made.

## Training procedure

- Candidates: majority-class baseline, logistic regression (raw inputs), random forest (raw inputs), random forest (raw + engineered features).
- Hyper-parameters: randomised search with 24 candidates scored by 5-fold stratified cross-validated PR-AUC on the training set.
- Final model: Random forest (raw + engineered features), selected for the highest cross-validated PR-AUC on the training set (0.902 ± 0.025); hold-out results played no part in the selection. Chosen hyper-parameters: `class_weight=None`, `max_depth=24`, `max_features=0.5`, `min_samples_leaf=1`, `n_estimators=400`.
- Operating threshold 0.349: maximises F2 on out-of-fold training scores (8000 rows, 271 failures). With beta = 2, recall counts four times as much as precision, which assumes that a missed failure costs more than an unnecessary inspection. That cost assumption is a design choice, not a measured fact.

## Interpretation and limitations

- **Synthetic data.** The labels follow documented rules (power outside 3,500–9,000 W, small temperature difference at low speed, wear × torque above a limit per product variant) plus random components. The model largely re-learns those rules; the results say how well a pipeline can recover them, not how well it would predict failures on real equipment.
- **Small number of failures.** The hold-out set contains 68 failures, so every metric has a wide interval (see above). Differences between the random-forest variants and the operating point should be read with that uncertainty in mind.
- **Threshold depends on assumed costs.** A different cost ratio between missed failures and unnecessary inspections would change the best threshold (see the threshold trade-off figure).
- **Score is not a probability.** See the reliability figure; do not read 0.35 as a 35% chance.
- **Extrapolation.** Inputs outside the training range (Air temp [K] 295.3 to 304.5, Process temp [K] 305.7 to 313.8, Speed [rpm] 1168 to 2886, Torque [Nm] 3.8 to 76.6, Tool wear [min] 0 to 253) get a warning in the dashboard; the model has not seen such conditions.
- **No temporal structure.** Records are independent snapshots; there is no sensor history, so trends and degradation over time are not modelled.
- **Not a confirmed fault.** A flag or a high score means "inspect", not "this machine is broken".
